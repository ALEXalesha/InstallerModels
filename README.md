# InstallerModels

Установщик моделей для ComfyUI. Качает их обратно с Hugging Face, если ты их удалил, чтобы освободить место.

Для LM Studio скачивания нет - там просто показываются точные названия, которые надо вбить в поиск.

Всего в манифесте 15 файлов на 95.4 ГиБ для ComfyUI и 2 модели на 7.2 ГиБ для LM Studio.

## Быстрый старт

Нужен только Python 3.8 или новее. Никаких зависимостей ставить не надо, всё на стандартной библиотеке.

Посмотреть, что вообще есть и что уже стоит:

```bash
python install.py --list
```

Поставить одну группу:

```bash
python install.py ltx
```

Поставить несколько сразу:

```bash
python install.py qwen sdxl audio
```

Поставить всё (95.4 ГиБ):

```bash
python install.py --all
```

Названия для LM Studio:

```bash
python install.py --lmstudio
```

## Группы моделей

Группы собраны по сохранённым воркфлоу в ComfyUI, не наугад. Каждая группа - это ровно те файлы, которые нужны одному воркфлоу.

| Группа | Размер | Что это | Воркфлоу |
|---|---|---|---|
| `ltx` | 40.0 ГиБ | LTX 2.3, видео из картинки и звука | `video_ltx2_3_ia2v.json` |
| `qwen` | 23.7 ГиБ | Qwen Image Edit 2509, редактирование картинок | `image_qwen_image_edit_2509.json` |
| `gemma` | 8.4 ГиБ | Gemma 4 E4B, генерация текста внутри ComfyUI | `llm_gemma4_text_gen.json` |
| `audio` | 7.2 ГиБ | ACE-Step v1 3.5B, генерация музыки | `audio_ace_step_1_t2a_song.json` |
| `sdxl` | 6.9 ГиБ | SDXL Juggernaut XI, генерация картинок | `Alex gen images.json` |
| `hunyuan3d` | 6.9 ГиБ | Hunyuan3D 2.1, картинка в 3D-меш | `3d_hunyuan3d-v2.1.json` |
| `clipvision` | 2.4 ГиБ | CLIP ViT-H-14 | ни один воркфлоу его не использует |

Полный список файлов с репозиториями и размерами - в [docs/models.md](docs/models.md).

## Все команды

| Команда | Что делает |
|---|---|
| `python install.py --list` | Список групп, размеры, что уже установлено |
| `python install.py --check` | Проверяет каждый файл на диске: есть, нет, или битый |
| `python install.py ГРУППА ...` | Ставит указанные группы |
| `python install.py --all` | Ставит всё |
| `python install.py --dry-run ГРУППА` | Показывает, что будет скачано, но не качает |
| `python install.py --lmstudio` | Названия моделей для LM Studio |
| `python install.py --root ПУТЬ` | Другая папка ComfyUI вместо той, что в `models.json` |

Код возврата 0 - всё хорошо, 1 - что-то не докачалось или не нашлось, 130 - прервали через Ctrl+C.

## Как это работает

Файлы качаются напрямую по `https://huggingface.co/РЕПО/resolve/main/ПУТЬ`. Токен Hugging Face не нужен, все репозитории открытые.

Докачка. Файл пишется в `имя.safetensors.part` рядом с целевым. Если оборвалось, при следующем запуске скрипт видит недокачанный кусок и просит у сервера остаток через HTTP-заголовок `Range`. Проверяется, что сервер ответил кодом 206, а не 200 - иначе он проигнорировал запрос диапазона и качать надо с нуля. Это проверено на практике: файл, докачанный с середины, побайтово совпал с оригиналом по sha256.

Проверка размера. У каждого файла в `models.json` записан точный размер в байтах, снятый с Hugging Face. После скачивания размер сверяется, и только потом `.part` переименовывается в настоящее имя. Если размер не сошёлся, файл остаётся `.part` и скрипт пишет об ошибке. Из-за этого в папке моделей никогда не появится файл с правильным именем и битым содержимым.

Уже установленное пропускается. Скрипт смотрит на размер файла на диске и, если он совпадает с ожидаемым, не трогает его.

Обрывы связи. Пять попыток на файл, пауза 5 секунд между ними. Каждая попытка продолжает с того места, где остановилась предыдущая. Если один файл в итоге не скачался, остальные всё равно качаются, а в конце выводится список неудачных. Просто запусти ту же команду ещё раз.

Место на диске. Перед скачиванием проверяется, хватает ли свободного места под всю очередь.

## Путь к ComfyUI

По умолчанию берётся из `models.json`, поле `comfyui_root`:

```
C:/Users/User/Documents/ComfyUI
```

Переопределить можно двумя способами, флаг главнее переменной:

```bash
python install.py --all --root "D:/ComfyUI"
```

```bash
set COMFYUI_ROOT=D:/ComfyUI
python install.py --all
```

## LM Studio

Скачивание LM Studio скрипт не делает специально. Если положить файлы в папку мимо приложения, оно может их не подхватить, пока не переиндексирует. Надёжнее скачать через само LM Studio.

| Что вбить в поиск | Квант | Размер |
|---|---|---|
| `lmstudio-community/gemma-4-E2B-it-GGUF` | Q4_K_M | 4.1 ГиБ |
| `lmstudio-community/Qwen3-VL-4B-Instruct-GGUF` | Q4_K_M | 3.1 ГиБ |

Обе модели с картинками на входе, поэтому к каждой идёт свой `mmproj`-файл. LM Studio подтянет его сам, отдельно скачивать не надо.

Через консоль, если установлен `lms`:

```bash
lms get lmstudio-community/gemma-4-E2B-it-GGUF
```

Подробности с именами файлов - в [docs/lmstudio.md](docs/lmstudio.md).

## Если поменялся состав моделей

Скрипт ничего не угадывает, он просто читает `models.json`. Чтобы добавить модель, допиши в нужную группу запись из четырёх полей:

```json
{
  "dest": "models/loras/моя-lora.safetensors",
  "repo": "автор/репозиторий",
  "path": "путь/внутри/репозитория.safetensors",
  "size": 123456789
}
```

Размер в байтах можно узнать так:

```bash
curl -sIL "https://huggingface.co/автор/репозиторий/resolve/main/путь.safetensors" | grep -i x-linked-size
```

Именно `x-linked-size`, а не `content-length`. Большие файлы на Hugging Face лежат в LFS, и `content-length` там показывает размер редиректа, а не самого файла.

## Известные ограничения

Качается по одному файлу за раз, в один поток. На 95 ГиБ это долго. Параллельная качалка вроде `hf_transfer` была бы быстрее, но потребовала бы ставить зависимости, а тут смысл в том, чтобы скрипт работал на голом Python.

Проверяется только размер, не контрольная сумма. Hugging Face не отдаёт sha256 обычным запросом, а считать хеш от 95 ГиБ на каждой проверке долго. Совпадение размера байт в байт отсекает все реальные случаи: оборванную закачку, пустой файл, не тот квант.

Ветка всегда `main`. Если автор репозитория удалит или переименует файл, скачивание упадёт с ошибкой 404. Тогда надо зайти на страницу репозитория и поправить `path` в `models.json`.
